# ITA 分钟行情清洗验收

2026-11-16（北京时间）。执行现行五周计划的四批清洗。已交付固定 499 股的分钟研究视图、逐键缺口、证券日收盘证据和后续端点。历史成分覆盖与独立竞价量额仍待补证。这份交付供数据阶段复核，ITA 的正式研究数据源沿用项目现行登记。

## 1. 冻结与抽检

核验 2016-01-04 至 2025-12-31 共 2,430 个日分片的 SHA-256。逐日重读 243,001,264 条唯一源分钟键，与历史证券日覆盖表逐键核对源行数。抽检用 2025-12-30 作为正常日，对照 2016-01-22、2016-06-20、2024-09-27。后二者分别是尾窗集中断档和上午异常的检查对象，2024-09-27 的已知市场屏蔽窗口为 10:23–11:13。 输入清单（本地 `artifacts/minute-cleaning/20261116T182000+0800/inputs.json`） · 抽检结果（本地 `artifacts/minute-cleaning/20261116T182000+0800/smoke.json`） · 验收清单（本地 `artifacts/minute-cleaning/20261116T182000+0800/verification.json`）

按证券代码加交易所、成分生效起止日含端点，与本地 Qlib 中证 500 清单对账。1,215,359 个名单证券日中，493,829 个落在固定证券池，493,592 个有源分钟行，覆盖 **40.61%**。本地名单涉及 1,263 只证券，其中 796 只完全在池外。逐日名单有 500 或 501 个唯一代码，名单尚待官方有效区间核验。覆盖率以这份本地名单为分母，源行存在也仅代表收到记录。休市不计入。 逐日对账（本地 `artifacts/minute-cleaning/20261116T182000+0800/csi500_overlap.csv`） · 缺失成员日（本地 `artifacts/minute-cleaning/20261116T182000+0800/csi500_missing.parquet`） · 固定池证券日覆盖（本地 `artifacts/minute-cleaning/20261116T182000+0800/minute_stock_days.parquet`）

## 2. 14:56 前固定窗口

窗口以源时间标签定位，13:56 为 60 阶滞后端点。窗口计算用实际成交证券日，全天停牌单列；两次市场熔断已提前结束交易，当天下午窗口非适用。临停内段同样标记非适用。分钟聚合边界沿用源标签，精确归桶仍待供应商确认。

## 3. 修订判定与日线端点

2016-06-20 的最后 61 个源标签中有 846 个集中断档或入账边界键。已有第二分钟归档在断档窗外也出现量额差异，逐键复核后继续沿用屏蔽。此次没有满足同键、同归桶及单位条件的新补录证据。已核日线更正和 3 个公司行动参考前收保留在独立证据字段中。分片仍使用既有版本化补丁。 归桶差异复核（本地 `artifacts/minute-cleaning/20261116T182000+0800/timing_gap_source_review.csv`） · 官方日线和公司行动（本地 `data/snapshots/artifacts/factor-library/min2016-25-official-followup/20261115T190000+0800/work_log.md`）

日线表有 996,232 个可用收盘及 12,851 个确认停牌证券日，438 个有归档的交易所收盘对照。复权收盘逐值核对冻结快照，限价来源与交易状态保留各自字段。996,232 个有交易的信号证券日中，994,096 个在冻结交易日历内同时有 d+1 和 d+2 收盘，覆盖 99.79%。该比率衡量价格端点，含红利收益和成交证据仍有各自条件。2026-01-05、01-06 的 264 个外部价格证据另表提供，仅覆盖此前目标样本。公司行动未逐股、逐日重新核验。 日线证据（本地 `artifacts/minute-cleaning/20261116T182000+0800/daily_evidence.parquet`） · 端点与原因（本地 `artifacts/minute-cleaning/20261116T182000+0800/endpoints.parquet`） · 期末外部证据（本地 `artifacts/minute-cleaning/20261116T182000+0800/external_endpoint_evidence_2026.parquet`）

## 字段与复现

| 交付 | 关键字段 |
| --- | --- |
| 现行分钟视图 | 在因子库目录调用 `minute_research.scan_minutes("YYYYMMDD")`。主键 `code, trade_time`，保留源时间、原状态、质量原因及补录来源。输入版本与哈希见输入清单。 |
| `windows_YYYY.parquet` | 主键 `code,date`。 `wN_expected` 为适用标签数，`wN_*_ok` 为该字段合格标签数，`wN_all` 为七字段同时合格的标签数。`lag60_*` 单列。覆盖汇总的 `labels=61` 行仅表示 13:56 单点。 |
| `gaps_YYYY.parquet` | 主键 `code,date,clock`。 `lag=0` 是 14:56，`lag=60` 是 13:56。 `applicable`、`reason`、字段资格布尔列用于区分缺失、双零以及非适用。排序表的 `window_label_impacts` 是缺口在各窗口中的累计次数。 |
| 日线与端点表 | 主键 `code,date`。 `raw_close` 单位元，`adjusted_close` 直接取冻结复权收盘；`d1`、`d2` 是冻结交易日历中的下一和再下一交易日。独立竞价量额字段为空，尾条量额保留在 `minute_shares`、`minute_yuan`。 |
